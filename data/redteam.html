⚠️ Rules of Engagement — Read This First Ethics ▶
Authorized Use Only
These Tools Are for Permission-Based Testing
Every tool in this domain is a reference for authorized penetration testing, CTF (Capture The Flag) competitions, home-lab practice, and cert prep (PenTest+, OSCP, CEH). Running them against systems you don't own or lack written permission to test is illegal in most jurisdictions (CFAA, Computer Misuse Act, etc.). Always work inside a signed scope / rules of engagement, stay within the authorized targets and time window, and handle any data you touch responsibly. Each card pairs offense with a blue-team detection note — because knowing how an attack looks on the wire is what makes you good at both sides.
🗺️ Nmap — The Network Mapper (Deep Dive) Recon ▶
Reference
The Swiss-Army Knife of Discovery
Nmap is the default tool for host discovery, port scanning, service/version detection, and OS (Operating System) fingerprinting. Its scripting engine (NSE) extends it into vuln checks and light exploitation. Authorized targets only.
▸ SCAN TYPES & ESSENTIALS
nmap -sS 10.0.0.0/24        # SYN "half-open" scan (default, fast, needs root)
nmap -sT target             # full TCP connect (no root)
nmap -sU target             # UDP scan (slow; DNS/SNMP/DHCP live here)
nmap -sV -O target          # service versions + OS detection
nmap -p- target             # all 65535 ports (default scans top 1000)
nmap -sC -sV -oA scan target # default scripts + versions, save all formats
nmap -T4 -Pn target          # faster timing; skip host-discovery ping
▸ NSE (SCRIPTING ENGINE)
FlagDoes
-sCRun the default safe script set
--script vulnKnown-vuln checks
--script smb-enum-sharesCategory/named scripts (~600 available)
-AAggressive: -sV -O -sC + traceroute
Blue-team note: a SYN scan shows up as many connections with no completed handshake from one source — IDS (Intrusion Detection System) (Suricata/Zeek) and firewall logs flag the fan-out. -T4/-T5 timing is loud; real adversaries scan slow.
⚡ Masscan & RustScan — Internet-Scale Port Discovery Recon ▶
Reference
When Nmap Is Too Slow
Masscan is an asynchronous scanner that can probe the entire IPv4 (Internet Protocol version 4) space in minutes by sending packets without waiting for replies. RustScan finds open ports fast, then hands them to Nmap for deep inspection — best of both. Authorized scope and rate limits only; unbounded scanning is disruptive. 
# Masscan — set a sane rate (packets/sec); high rates can DoS the target
masscan 10.0.0.0/16 -p1-65535 --rate 1000 -oL out.txt

# RustScan → auto-pipe discovered ports into nmap -sV -sC
rustscan -a target --range 1-65535 -- -sV -sC
Blue-team note: extremely high packet rates from a single IP (Internet Protocol) to sequential ports are the signature — netflow/IDS thresholds catch it instantly. Attackers throttle to blend in.
🌾 theHarvester & Recon-ng — OSINT (Open Source Intelligence) Frameworks OSINT ▶
Reference
Passive Intelligence Before You Touch the Target
theHarvester gathers emails, subdomains, hosts, and names from public sources (search engines, certificate transparency, PGP keyservers). Recon-ng is a full framework with a Metasploit-style module system for structured OSINT into a local database. These are passive — they query third parties, not the target directly. 
theHarvester -d example.com -b all      # emails/subdomains from all sources

# Recon-ng — modular, DB-backed
recon-ng
[recon-ng] > marketplace install all
[recon-ng] > modules load recon/domains-hosts/hackertarget
[recon-ng] > options set SOURCE example.com
[recon-ng] > run
Blue-team note: passive OSINT is nearly invisible to the target — the defense is reducing your footprint: scrub metadata, limit what's public, monitor certificate-transparency logs for look-alike domains.
🔭 Amass & Subfinder — Subdomain Enumeration OSINT ▶
Reference
Mapping the Full Attack Surface
Organizations expose far more subdomains than they realize — dev, staging, forgotten apps. Amass (OWASP) and Subfinder aggregate dozens of sources (cert transparency, DNS, APIs) to enumerate them. Finding the forgotten old-admin.example.com is often the way in. 
subfinder -d example.com -all -o subs.txt   # fast, passive
amass enum -passive -d example.com            # passive aggregation
amass enum -active -d example.com -brute       # active: resolves + brute-forces
Blue-team note: maintain your own asset inventory the same way — you can't defend subdomains you forgot you own. Watch for dangling DNS (Domain Name System) records (subdomain takeover risk).

🧪 Burp Suite — The Web Pentest Workbench Web ▶
Reference
Intercept, Modify, Replay
Burp Suite is the industry-standard web app testing platform. It sits as a proxy between your browser and the target, letting you inspect and tamper with every request. Authorized targets only.
ToolDoes
ProxyIntercept + edit requests/responses on the fly
RepeaterManually tweak & resend a single request (the core manual-testing loop)
IntruderAutomate payloads over positions — fuzzing, brute force, enumeration
ScannerAutomated vuln crawl (Pro)

Typical flow: browse the app through the proxy to map it → send an interesting request to Repeater → probe for injection/auth flaws by hand → automate with Intruder. Blue-team note: app-layer WAF (Web Application Firewall) + anomaly detection on parameter tampering and high request volume from one session.
⚡ OWASP (Open Worldwide Application Security Project) ZAP — The Open-Source Web Scanner Web ▶
Reference
Burp's Free Cousin — Great for CI
OWASP ZAP is a free, open-source web proxy/scanner with much of Burp's core: intercepting proxy, spider, active/passive scanning, and fuzzing. Its automation-friendliness makes it the go-to for DAST (Dynamic Application Security Testing) in CI/CD (Continuous Integration / Continuous Delivery) — run a baseline scan on every build against a staging deploy. 
# Baseline (passive) scan — safe for CI, no attacks
zap-baseline.py -t https://staging.example.com

# Full active scan (authorized targets only)
zap-full-scan.py -t https://staging.example.com
Blue-team crossover: because ZAP is a defensive tool too, wire it into your own pipeline to catch OWASP Top 10 regressions before release.
💉 sqlmap — Automated SQL (Structured Query Language) Injection Web ▶
Reference
Detect & Exploit SQLi, End to End
sqlmap automates finding and exploiting SQL injection — from detection through data extraction, and even OS (Operating System) shell where the DB permits. Powerful and noisy; authorized scope only. 
sqlmap -u "https://site/item?id=1" --batch    # test a parameter
sqlmap -r request.txt --level 3 --risk 2   # from a saved Burp request
sqlmap -u "..." --dbs                     # list databases
sqlmap -u "..." -D shop -T users --dump    # dump a table
FlagMeaning
--level / --riskHow hard/aggressive to test (1–5 / 1–3)
--tamperEvasion scripts (encode payloads past filters/WAF)
--batchNon-interactive (accept defaults)
Blue-team note: the fix is parameterized queries, not a WAF (Web Application Firewall) — but a WAF + DB query logging will scream at sqlmap's payload patterns and error-based probing.
📁 ffuf & Gobuster — Content & Parameter Fuzzing Web ▶
Reference
Finding the Hidden Endpoints
Web apps hide directories, files, vhosts, and parameters that aren't linked anywhere. ffuf (fast, Go) and Gobuster brute-force them from a wordlist — finding /admin, /backup.zip, or an undocumented API (Application Programming Interface) parameter. Authorized scope only. 
# Directory discovery — FUZZ marks the injection point
ffuf -u https://site/FUZZ -w wordlist.txt

# Filter noise by response size / status
ffuf -u https://site/FUZZ -w list.txt -fc 404 -fs 0

# Virtual-host discovery
ffuf -u https://site -H "Host: FUZZ.site" -w vhosts.txt

# Gobuster equivalent
gobuster dir -u https://site -w wordlist.txt
Blue-team note: a flood of 404s to random paths from one source is the signature — rate-limit and alert on it. Common wordlists come from SecLists.
🎯 Nuclei — Templated Vulnerability Scanning Web ▶
Reference
Community-Powered Checks at Scale
Nuclei runs thousands of YAML-defined templates against targets to detect known CVEs (Common Vulnerabilities and Exposures), misconfigurations, exposed panels, and default creds — fast and low-false-positive. Dual-use: attackers find weak spots; defenders scan their own estate the same way. 
nuclei -u https://site                    # all default templates
nuclei -l hosts.txt -t cves/ -severity critical,high
nuclei -u https://site -t exposures/       # exposed configs/keys
Blue-team note: run Nuclei against your own external surface on a schedule — it's one of the fastest ways to catch a newly-disclosed CVE affecting you before an attacker does.
🔬 Nikto & WPScan — Server & CMS Scanning Web ▶
Reference
Quick Wins on Web Servers & WordPress
Nikto is a fast (loud) web-server scanner for known dangerous files, outdated software, and misconfigurations. WPScan targets WordPress specifically — enumerating plugins/themes/users and matching them to known vulns (WordPress powers ~40% of the web, so it's a huge attack surface). Authorized targets only. 
nikto -h https://site                       # server misconfig sweep
wpscan --url https://site --enumerate vp,u   # vuln plugins + users
Blue-team note: both are extremely noisy — trivially caught by IDS/WAF. Defense is patching, removing version banners, and keeping CMS plugins minimal and current.

🗃️ Searchsploit & Exploit-DB — Finding Public Exploits Exploitation ▶
Reference
Match a Version to a Known Exploit
Once enumeration gives you exact software versions, the question is: is there a public exploit? Exploit-DB is the archive; searchsploit is its offline CLI (Command Line Interface) (ships with Kali). Vet before you run — public PoCs (Proof of Concept) can be broken, or booby-trapped. 
searchsploit apache 2.4          # find exploits for a version
searchsploit -x php/webapps/1234  # view the exploit source
searchsploit -m php/webapps/1234  # copy it locally to inspect/edit
Blue-team note: this is why version-hiding + fast patching matter — the entire chain is "know the version → look up the exploit." Remove version banners and keep software current.
🐍 Impacket — The Windows/AD Python Toolkit Exploitation ▶
Reference
Speak Windows Protocols From Linux
Impacket is a collection of Python scripts that implement Windows network protocols (SMB, Kerberos, MSRPC) — the backbone of hands-on Active Directory testing. It lets you move laterally, dump creds, and execute commands with credentials you've legitimately obtained during an engagement. Authorized AD environments only.
ScriptDoes

🔓 Mimikatz — Credential Extraction AD Attacks ▶
Reference
The Tool That Redefined AD (Active Directory) Security
Mimikatz extracts plaintext passwords, hashes, and Kerberos tickets from Windows memory (LSASS), and forges tickets. It's the canonical post-exploitation credential tool — understanding it is essential for both attack and defense. Authorized, lab, and cert-prep contexts only.
TechniqueWhat
sekurlsa::logonpasswordsDump creds/hashes from LSASS (Local Security Authority Subsystem Service) memory
Pass-the-HashAuthenticate with an NTLM (NT LAN Manager) hash — no password needed
Pass-the-TicketReuse a stolen Kerberos ticket
Golden TicketForge a TGT (Ticket Granting Ticket) with the krbtgt hash — domain-wide persistence
DCSyncImpersonate a DC to pull password hashes via replication
Blue-team note: defenses are Credential Guard (protects LSASS), LSASS-access alerts (Sysmon event 10), disabling NTLM where possible, and watching for anomalous replication (DCSync = event 4662 from a non-DC).
🎟️ Kerberos Attacks — Rubeus & Kerbrute AD Attacks ▶
Reference
Abusing the Ticket System
Kerberos is AD (Active Directory)'s auth protocol — and its ticketing has abusable quirks. Rubeus is the Swiss-army knife for ticket attacks; Kerbrute does fast username enumeration and password spraying against the KDC (Key Distribution Center). Authorized environments only.
AttackIdea
KerberoastingRequest service tickets (SPNs), crack them offline for the service account password
AS-REP RoastingAccounts with "no pre-auth" leak a crackable hash without any creds
Password sprayOne password against many users (avoids lockout)
Silver TicketForge a service ticket with a service account hash
Blue-team note: Kerberoasting shows as a spike of TGS (Ticket Granting Service) requests (event 4769) for many SPNs (Service Principal Name) from one user. Defenses: long, random service-account passwords (or gMSAs), and enabling Kerberos pre-auth.
🕸️ Responder & NTLM (NT LAN Manager) Relay AD Attacks ▶
Reference
Poison the LAN (Local Area Network), Capture the Auth
Responder answers broadcast name-resolution requests (LLMNR/NBT-NS/mDNS) that Windows sends when DNS (Domain Name System) fails — tricking hosts into authenticating to the attacker and leaking NetNTLM hashes. Combined with ntlmrelayx, the captured auth is relayed to another host to gain access without ever cracking a hash. Authorized internal engagements only.
Blue-team note: this is one of the most common real-world internal footholds. Defenses are concrete and high-impact: disable LLMNR (Link-Local Multicast Name Resolution) and NBT-NS (NetBIOS Name Service) via GPO (Group Policy Object), enforce SMB (Server Message Block) signing (breaks relay), and segment the network. Detection: a host suddenly answering name queries for everything.
📜 ADCS Abuse — Certipy & the ESC Techniques AD Attacks ▶
Reference
When the Certificate Authority Becomes the Backdoor
Active Directory Certificate Services (ADCS) issues certs — and misconfigured templates let a low-priv user request a certificate that authenticates as someone else, up to Domain Admin. Certipy finds and exploits these (the "ESC1–ESC8" family). It's become one of the most impactful AD (Active Directory) attack classes. Authorized assessments only.
StepDetail
Findcertipy find — enumerate templates & flag vulnerable ones
ESC1Template lets requester supply the subject → request a cert as any user
AuthenticateUse the cert to get a TGT (Ticket Granting Ticket) / NTLM (NT LAN Manager) hash for that identity
Blue-team note: audit certificate templates (remove "enrollee supplies subject" + client-auth combos), monitor the CA (Certificate Authority)'s issuance logs, and restrict enrollment rights. Certipy's own find is the fastest way for defenders to spot the misconfig first.
📻 C2 (Command and Control) Concepts — Beacons, Listeners & Redirectors C2 ▶
Reference
How Operators Control an Authorized Foothold
Command & Control (C2) is how a red-team operator communicates with an implant on a compromised host during an authorized engagement. Understanding the architecture is essential for blue teams — it's the most-detected phase of an attack, and maps to MITRE ATT&CK (Adversarial Tactics, Techniques and Common Knowledge)'s Command & Control tactic. Reference for authorized red-team / CRTO-style cert prep and detection engineering.
TermRole
Implant / BeaconCode on the host that calls back for tasking
Listener / Team ServerThe operator side the implant connects to
RedirectorA relay that hides the real team server
Beacon interval / jitterHow often (and how randomly) it checks in
ChannelHTTPS (HyperText Transfer Protocol Secure), DNS (Domain Name System), SMB (Server Message Block) — how tasking is carried
Blue-team detection: beaconing shows up as regular, periodic outbound connections to one destination — even over HTTPS, the timing pattern betrays it. Zeek/SIEM analytics on connection intervals, JA3/TLS fingerprints, and newly-seen domains are the classic catches.

🦠 Sliver — The Open-Source Modern C2 (Command and Control) C2 ▶
Reference
The Free Alternative Red Teams Adopted
Sliver (BishopFox) is a popular open-source, cross-platform C2 framework — a common Cobalt Strike alternative for budgets and labs. 🔥 Hashcat — GPU (Graphics Processing Unit) Password Cracking Passwords ▶
Reference
The Fastest Way to Recover Passwords From Hashes
Hashcat cracks password hashes using the GPU, trying billions of guesses per second. In an authorized engagement you feed it hashes you legitimately captured (e.g. from an NTDS dump) to demonstrate weak passwords. Authorized assessment / cert-prep / your-own-hashes only.
▸ ATTACK MODES
ModeHow
Dictionary (-a 0)Try each word in a wordlist
+ Rules (-r)Mutate words (Password→P@ssw0rd!) — huge multiplier
Mask (-a 3)Brute-force a known pattern (?u?l?l?l?d?d)
Combinator (-a 1)Join two wordlists
# NTLM hashes, rockyou wordlist + best64 rules
hashcat -m 1000 -a 0 hashes.txt rockyou.txt -r rules/best64.rule
Blue-team note: cracking is offline (nothing to detect on the wire) — the defense is upstream: long passphrases, slow hashes (bcrypt/argon2, not fast MD5/NTLM), and stopping the hash theft in the first place.
🃏 John the Ripper — The Versatile Cracker Passwords ▶
Reference
Auto-Detect & Crack Almost Anything
John the Ripper (the "jumbo" build especially) is the veteran CPU (Central Processing Unit) cracker — great at auto-detecting hash formats and packed with *2john helpers that extract crackable hashes from files (ZIP, PDF, SSH keys, KeePass). Authorized use only. 
# Extract a hash from a protected file, then crack it
zip2john secret.zip > hash.txt
john --wordlist=rockyou.txt hash.txt
john --show hash.txt            # reveal cracked passwords
When to use which: Hashcat for raw GPU (Graphics Processing Unit) speed on big hash lists; John for format auto-detection, the *2john extractors, and quick CPU jobs. Most operators keep both.
🚪 Hydra & Medusa — Online Login Attacks Passwords ▶
Reference
Brute-Forcing Live Services (Loudly)
Where Hashcat/John are offline, Hydra and Medusa attack live logins — SSH (Secure Shell), RDP (Remote Desktop Protocol), HTTP (HyperText Transfer Protocol) forms, databases — trying credentials over the network. Password spraying (one password vs many users) is usually smarter than brute-forcing one account into a lockout. Authorized targets only; this is noisy and can lock accounts. 
# SSH, one user, a wordlist (authorized lab host)
hydra -l admin -P passwords.txt ssh://10.0.0.5

# Spray one password across many users
hydra -L users.txt -p 'Spring2026!' ssh://10.0.0.5
Blue-team note: online attacks are very detectable — bursts of failed logins (Windows 4625, SSH auth failures) from one source. Defenses: lockout/backoff, MFA (Multi-Factor Authentication), and rate-limiting. Spraying is stealthier but still shows as many users failing with the same password.

📶 Aircrack-ng — Wi-Fi Auditing Suite Wireless ▶
Reference
Capture the Handshake, Test the Passphrase
Aircrack-ng is the classic suite for assessing Wi-Fi security: put a card in monitor mode, capture the WPA2 (Wi-Fi Protected Access 2) 4-way handshake, and test it against a wordlist offline. Only on networks you own or are authorized to test — intercepting others' Wi-Fi is illegal.
ToolStep

airodump-ngScan APs/clients; capture the handshake

Blue-team note: deauth floods are detectable by WIDS/WIPS. Defenses: WPA3 (Wi-Fi Protected Access 3) (resists offline cracking), long random passphrases, 802.1X/enterprise auth instead of a shared PSK.
📡 Wifite & hcxdumptool — Automated Wi-Fi & PMKID (Pairwise Master Key Identifier) Wireless ▶
Reference
One Command, Modern Attacks
Wifite automates the whole aircrack workflow across all nearby networks. hcxdumptool enables the PMKID attack — grabbing a crackable value from an AP without needing a connected client or a deauth, making it faster and quieter than the classic handshake capture. Authorized networks only.
Blue-team note: PMKID works against APs that include the value in the first handshake message; disabling it where possible, and (again) WPA3 (Wi-Fi Protected Access 3) + strong passphrases, is the mitigation. The captured hash still has to be cracked offline — long passphrases defeat it.

🐬 Flipper Zero & Sub-GHz / RFID (Radio Frequency Identification) Tools Hardware ▶

🪛 Living off the Land — LOLBAS & GTFOBins Post-Ex ▶
Reference
Turning Built-In Tools Into Weapons
Attackers avoid dropping malware by abusing legitimate, pre-installed binaries — "living off the land". On Windows, LOLBAS catalogs signed binaries that can download, execute, or bypass controls; on Linux, GTFOBins lists how common utilities can break out of restricted shells or escalate. Study/detection reference for authorized testing.
ExampleAbuse
certutilDownloads files (looks like a cert tool)
regsvr32 / mshtaExecutes remote scripts
rundll32Runs code via a DLL (Dynamic Link Library) export
bash/vim/find (GTFOBins)Shell escape / privesc from a limited context
Blue-team note: signatures don't help — these are trusted binaries. Detection is behavioral: certutil making a network connection, or winword.exe spawning powershell.exe, is anomalous even though every binary is signed (this is why Sysmon parent/child chains matter).
🧗 Privilege Escalation Scanners — PEAS & PowerUp Post-Ex ▶
Reference
From User to Root/SYSTEM
After landing a low-priv foothold, operators enumerate the host for escalation paths. linPEAS/winPEAS (and PowerUp/PrivescCheck) automate the checklist — misconfigured services, weak permissions, stored creds, kernel exploits, SUID (Set User ID) binaries. Authorized hosts only.
Finds (Windows)Finds (Linux)
Unquoted service pathsSUID/SGID binaries (GTFOBins)
Writable service binariesWritable /etc/passwd, cron jobs
AlwaysInstallElevatedSudo misconfigs (NOPASSWD)
Stored creds / autologonKernel version → known exploits
Blue-team note: PEAS scans touch a huge number of files/registry keys quickly — noisy to EDR (Endpoint Detection and Response). Defense is the fix, not the detect: least privilege, patch, remove SUID, lock down sudo, no creds on disk.
🌉 Pivoting & Tunneling — Chisel, ligolo-ng & proxychains Post-Ex ▶
Reference
Reaching Networks You Can't Route To
A compromised host is often a pivot into segments the operator can't reach directly. Tunneling tools route traffic through the foothold so tools on the attacker box can hit internal systems. Authorized, scoped internal networks only.
ToolRole
ChiselFast TCP/UDP tunnel over HTTP (HyperText Transfer Protocol) (SOCKS proxy through the pivot)
ligolo-ngModern tunneling with a virtual interface (route to internal subnets)
SSH (Secure Shell) -D / -LDynamic (SOCKS) & local port forwarding

☁️ Pacu — The AWS (Amazon Web Services) Exploitation Framework Cloud Offense ▶
Reference
Metasploit, But for AWS
Pacu (Rhino Security Labs) is a modular framework for testing AWS environments — once you have a set of credentials (legitimately, in an authorized assessment), it enumerates permissions, finds privilege-escalation paths, and demonstrates impact. Authorized cloud assessments only.
Module typeDoes
enumMap what the creds can see (IAM, EC2, S3, Lambda)
privescFind IAM (Identity and Access Management) misconfig chains (iam:PassRole etc.)
persistence / exfilDemonstrate impact for the report
Blue-team note: everything Pacu does is API (Application Programming Interface) calls — CloudTrail + GuardDuty see the enumeration and privesc attempts. This is the offensive mirror of the CSPM (Cloud Security Posture Management) tools in the Cloud domain.
🦊 CloudFox & enumerate-iam — Attack-Surface Enumeration Cloud Offense ▶
Reference
"What Can I Do With These Creds?"
After obtaining cloud credentials during an engagement, the first question is what they grant. CloudFox surfaces exploitable attack paths (roles you can assume, secrets you can read, instances you can reach); enumerate-iam brute-forces which API (Application Programming Interface) calls a set of keys is allowed to make. Authorized use only.
Blue-team note: these produce a burst of describe/list and access-denied events in CloudTrail — a spike of AccessDenied from one principal is a strong enumeration signal. Least privilege shrinks what any leaked key can enumerate in the first place.
☸️ Kubernetes Attacks — RBAC (Role-Based Access Control) Abuse & Container Escape Cloud Offense ▶
Reference
From a Pod to the Cluster
A compromised container is the start, not the end. Attackers abuse over-permissive RBAC, over-mounted service-account tokens, and privileged/host configs to escape a pod and take over the node or cluster. kube-hunter (and kubeaudit) probe for these. Authorized clusters only.
WeaknessImpact
Over-broad RBACA pod's token can create pods / read secrets cluster-wide
Privileged / hostPath podEscape to the node's filesystem/kernel
Exposed kubelet / API (Application Programming Interface)Direct command execution on pods
Mounted SA tokenDefault token used to call the API
Blue-team note: this is exactly what the Kubernetes Security card defends — least-privilege RBAC, Pod Security Standards (no privileged/hostPath), network policies, and audit logging.
🎭 Cloud Credential Attacks & the Purple-Team Bridge Cloud Offense ▶
Reference
SSRF (Server-Side Request Forgery) → Metadata → Role, and Closing the Loop
The signature cloud breach chain: an app-layer SSRF is used to reach the instance metadata service (IMDS), steal the attached role's temporary credentials, then pivot with those creds. Understanding it is what lets red and blue close the loop together (purple teaming).
StepDefense
SSRF in the appFix the vuln; validate/deny internal URLs (Uniform Resource Locator)
Hit IMDS for credsEnforce IMDSv2 (session-token, blocks basic SSRF)
Use stolen role credsLeast privilege; detect creds used off-instance (GuardDuty)
Purple team: the red team demonstrates the chain against ATT&CK (Adversarial Tactics, Techniques and Common Knowledge); the blue team confirms each step is detected/blocked (IMDSv2, CSPM, GuardDuty). That collaboration — offense proving, defense hardening — is the whole point of pairing these two domains.
