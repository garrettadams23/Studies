🖼️ How the Browser Renders a Page Browser ▶
Concept
From Bytes to Pixels
Understanding the rendering pipeline is what separates people who "write CSS (Cascading Style Sheets)" from people who make fast sites. The browser turns your HTML/CSS into pixels through a fixed sequence of steps.
StepDoes
Parse → DOMHTML (HyperText Markup Language) becomes the Document Object Model tree
Parse → CSSOMCSS becomes the style tree
Render treeDOM + CSSOM combined (visible nodes only)
Layout (reflow)Compute geometry — where & how big everything is
PaintFill in pixels (text, colors, borders)
CompositeAssemble layers on the GPU (Graphics Processing Unit)
Render-blocking: CSS blocks rendering (the browser won't paint unstyled content); a plain <script> blocks parsing. Use defer/async and keep critical CSS small so the page paints fast.
🌀 Reflow, Repaint & What Causes Jank Performance ▶
Concept
Why Animations Stutter
To hit 60fps the browser has ~16ms per frame. Reflow (recomputing layout) is expensive; repaint is cheaper; compositing a transform is cheapest. Triggering layout every frame causes jank.
ChangeCost
width/height/top/leftReflow (layout) — avoid animating these
color/backgroundRepaint only
transform / opacityComposite only — GPU (Graphics Processing Unit), no layout (animate these!)
Layout thrashing: reading a layout property (like offsetHeight) right after writing one forces a synchronous reflow in a loop. Batch reads, then writes. Animate transform and opacity — they skip layout and paint entirely.
🌳 The DOM (Document Object Model) & Events — Bubbling & Delegation Browser ▶
Reference
How Clicks Travel Through the Page
The DOM is the live tree of the page that JavaScript manipulates. Events flow through it in phases — understanding this powers efficient event handling. 
// Event delegation: one listener for many children
list.addEventListener('click', (e) => {
  const item = e.target.closest('.item');
  if (item) select(item.dataset.id);
});
PhaseDetail
CaptureTop → target (rarely used)
TargetThe element clicked
BubbleTarget → top (default for listeners)
Delegation attaches one listener to a parent and uses bubbling to handle any child — essential for dynamic lists (no re-binding on add/remove). stopPropagation() halts bubbling; preventDefault() stops the browser's default action.

🔒 Closures, Scope & this JavaScript ▶

⏳ Async Deep — Promises, await & the Event Loop JavaScript ▶
Concept
How Single-Threaded JS Does Many Things
JavaScript runs on one thread but stays responsive via the event loop: long operations (network, timers) run elsewhere and their callbacks are queued back. Promises and async/await make this readable. 
async function load() {
  try {
    const [a, b] = await Promise.all([getA(), getB()]); // parallel
    return merge(a, b);
  } catch (e) { handle(e); }
}
ConceptDetail
PromiseA value that arrives later (pending → fulfilled/rejected)
async/awaitWrite async code that reads like sync
Microtask vs macrotaskPromises (micro) run before timers (macro)
Promise.all / race / allSettledCoordinate multiple promises
Parallel vs serial: await a; await b; runs one after the other; Promise.all([a,b]) runs them together — a common performance win. Never await in a loop when the iterations are independent.

🔌 Fetch, REST (Representational State Transfer) & CORS (Cross-Origin Resource Sharing) in Practice Backends ▶

🌍 Internationalization (i18n) — Designing for Languages You Do Not Speak Quality ▶
Concept
i18n Is Not Translation — It Is Removing the Assumptions That Make Translation Impossible
The two words are used interchangeably and mean opposite halves of the job. Localization (l10n) is producing the French: translators, glossaries, a review cycle. Internationalization (i18n) is everything you do first so that producing the French is possible at all — and essentially all of it is removing English grammar and English typography from your code. It is engineering work, it happens before a single string is sent anywhere, and it is very cheap now and very expensive in two years. The costly version is not the translation budget; it is discovering that fixing the code is a rewrite of every screen.
The tell that a codebase was never internationalized is not the absence of a translation file. It is string concatenation in the view layer, and it is visible in one grep.
Concept
The Concatenation Bug, Which Is the Whole Subject in One Line
This looks harmless and cannot be translated by anyone, at any budget: 
// Untranslatable — three separate mistakes
"You have " + n + (n === 1 ? " message" : " messages")

// Translatable — one string, named placeholder, plural handled by the format
t("inbox.count", { count: n })
  en: "{count, plural, one {You have # message} other {You have # messages}}"
  pl: "{count, plural, one {...} few {...} many {...} other {...}}"
Assumption baked inWhere it fails
Word order is subject-verb-objectJapanese and Turkish put the verb last; a translator cannot reorder fragments your code will re-join
Plural means "one" versus "not one"Polish and Russian have few and many; Arabic uses six categories; Japanese uses one
Zero is just another plural"You have 0 messages" is grammatical; "No messages" is what a human writes, and only a message format lets a translator choose
Gender does not affect the sentenceIn Spanish and Hebrew the surrounding words change with the subject's gender — so the variable has to be inside the translated string
The rule that prevents all of it: a translator must receive whole sentences with named placeholders, never fragments. If a translator cannot move a placeholder to the other end of the sentence, the string is broken regardless of how correct the English reads.
Reference
Never Format These By Hand
Every runtime worth using ships a locale database. Hand-rolling any row of this table is how a product ends up telling a German user that something costs 1,234.50 € when it should say 1.234,50 €.
ThingUseWhat varies that you would not guess
NumbersIntl.NumberFormatDecimal comma; grouping by 2s in India (12,34,567); non-Western digits
CurrencyIntl.NumberFormat with a currency codeSymbol position, spacing, and the number of decimal places — JPY has none
DatesIntl.DateTimeFormatOrder, separators, 12- versus 24-hour, and which day the week starts on
Relative timeIntl.RelativeTimeFormat"3 days ago" declines differently and is not always a suffix
ListsIntl.ListFormatThe Oxford comma is not universal, and neither is "and"
SortingIntl.CollatorSwedish sorts å after z; German sorts it with a. Same characters, different order, both correct
Case changesLocale-aware toLocaleUpperCaseTurkish dotted and dotless i — the classic bug that breaks a login form in exactly one country
A locale is not a language: pt-BR and pt-PT differ in vocabulary and formatting, and en-GB and en-US disagree about the date order in a way that silently produces the wrong day for eleven days a month. Store and negotiate full locale tags, not two-letter languages.
Concept
Layout: Text Expands, and Some of It Runs the Other Way
Translated text is routinely much longer than the English — German and Finnish especially, and short strings expand proportionally most, so buttons and labels break before paragraphs do. Any container sized to fit the English is a defect waiting for a translation file.
ProblemFix
Fixed-width buttons and nav itemsSize from content, allow wrapping, and never truncate a control's label
Text baked into imagesReal text over the image, or one asset per locale — an image is not translatable
Right-to-left languagesdir="rtl" plus logical CSS (Cascading Style Sheets) properties — margin-inline-start, not margin-left — so the whole layout mirrors from one attribute
Icons in RTLDirectional icons mirror (back arrows, progress); representational ones do not (clocks, logos, a play button on media)
Mixed direction in one lineA phone number or Latin brand name inside Arabic text needs bidi isolation (<bdi> or unicode-bidi: isolate), or punctuation jumps to the wrong end
Truncating with substringCuts through emoji and Indic clusters. Use a segmenter, or fade with CSS instead of slicing
The length assumption hides in one more place: a "character" is not a byte, a code point, or a visible glyph. A single family emoji is one thing on screen and several code units in JavaScript, so a database column sized in characters, a validator counting .length, and a user counting what they can see will all disagree. Encoding — Bytes, Text, and Why "It Works on My Machine" is the same trap one layer down.
Concept
The Assumptions Hiding in Your Forms
Personal data models leak the developer's own country more reliably than anything else in the codebase, and each of these locks out real users rather than merely annoying them.
AssumptionReality
First name and last nameMany people have one name, several family names, or a family name written first. Store a full name and, only if you genuinely need it, a separate display name
A state or province is requiredMost countries do not have one
Postcodes match a patternFormats vary and some places have none. Validate per country, or not at all
Addresses have a fixed shapeField order and which lines exist differ; render the address form from the selected country
Phone numbers are nationalStore E.164 with the country code, and never strip a leading +
Everyone shares a calendarWorking weeks differ, and public holidays are per-country business logic, not a constant
Time deserves its own warning. Store instants in UTC (Coordinated Universal Time) and render in the viewer's zone — but "the day" is a local concept: a birthday, an opening time and a monthly billing date have no timezone at all, and converting them to UTC is what makes them arrive a day early for half the world. Dates, Times & Time Zones covers the storage side.
Concept
Testing It Before Anything Is Translated
The reason i18n bugs ship is that they are invisible until a real translation arrives, which is usually after the design is frozen. Pseudo-localization removes that dependency: generate a fake locale from the English by accenting every character, padding the string, and bracketing it. 
Save changes   →   [!!! Šàvé çhàngéš —— ]

Reads in English, so you can still use the app.
Three defects become visible immediately:
  • Any string still in plain English is hardcoded and never reached the catalogue.
  • Any text overflowing its box will overflow in German.
  • Any missing bracket is a sentence assembled from fragments at runtime.
GateCatches
Pseudo-locale build in CIHardcoded strings and layout overflow, on every pull request
Lint rule against literal JSX (JavaScript XML) textThe concatenation habit, at the point it is written
Screenshot review in one RTL localePhysical CSS properties that did not mirror
Translator context notes on each key"Open" as a verb versus an adjective — the ambiguity no format string can express
The order that keeps the cost low: extract strings, adopt a message format with plural support, switch to logical CSS properties, and turn on the pseudo-locale — all before choosing a translation vendor. Do it in that order and the first real language is a configuration change; do it after, and it is a redesign.
🧰 Accessibility Remediation — Working Through an Audit Backlog A11y ▶
Concept
The Audit Gives You Violations; Users Have Tasks They Cannot Finish
Web Accessibility (a11y) — WCAG & ARIA is the standard. This is what happens after someone runs it against a real codebase and hands you four hundred findings. The instinct is to sort by the tool's severity label and start at the top, and it is the wrong sort: severity describes how badly a guideline is broken, not whether anybody is stopped. A low-contrast footer link is flagged; a submit button with no accessible name ends the session. Both appear on the list, and only one of them is losing you users today.
TierTestExamples
BlockerA task cannot be completed at all by some userUnlabelled controls; keyboard traps; a modal that does not take focus; a custom control with no keyboard path; an error that is never announced
SevereCompletable, but hostileIllogical focus order; icon-only buttons; a table with no header association; missing skip link on a long nav
CosmeticNon-conformant, no functional impactContrast on a decorative element; a redundant landmark; a heading level skipped once
Then order the blockers by flow, not by page: sign-in, checkout, and anything that carries money or identity go first, because those are the tasks a person cannot simply do somewhere else on your site. A marketing page with the same violation is a smaller problem in exactly the way it sounds.
Concept
Four Hundred Violations Are Usually Twelve Components
This is the single most useful fact about remediation, and it is invisible in the report. Automated tools count instances — one per rendered element, per page, per state. A date picker used on thirty screens produces thirty findings and one bug. Regrouping the report by component before planning anything changes the job from an unbounded page-by-page slog into a bounded list with an end.
Counted asEffect
Instances (the report's own number)The burndown barely moves for weeks, the work looks endless, and the team stops believing the number
Components (after regrouping)Fixing one shared control closes dozens of findings at once, and progress is visible from the first week
It also settles where the fix belongs. If the accessible name has to be added in thirty call sites, the component is wrong; fix it once, inside, and let every call site inherit it. A design system is the highest-leverage accessibility investment available for the same reason it is the highest-leverage anything: the fix applies to code not yet written.
Reference
What Automation Finds, and What It Cannot
Automated scanning catches a real but minority share of accessibility problems — the ones expressible as a rule about markup. It is genuinely valuable and it is not a verdict, and knowing which column a question falls into stops a lot of wasted argument.
Automation findsOnly a human finds
Missing alt attributeWhether the alt text describes the right thing, or restates the caption
Contrast below thresholdWhether the focus indicator is visible against the component it sits on
Form control with no accessible nameWhether the name matches the visible label a voice-control user will say
Invalid ARIA (Accessible Rich Internet Applications) attribute or roleWhether the role is a lie — a div with role="button" and no key handling
Duplicate id, missing langWhether the reading order makes sense, or errors reach the user at all
The manual pass is short and does not need specialist tooling. Unplug the mouse and complete the flow: can you reach every control, is focus always visible, does anything trap you? Then zoom to 400% and check nothing is cut off or overlapped. Then run a screen reader through the same flow. Those three passes find most of the right-hand column, and the first one takes minutes. Accessible IT — Assistive Technology, Procurement & Testing Your Own Tools covers the same testing habit applied to the tools you buy rather than the ones you build.
Concept
Fixes Decay Unless Something Enforces Them
The predictable end of a remediation project is a re-audit eighteen months later finding a similar count. Nothing was undone; new code simply arrived without the same care. Remediation that is not accompanied by a gate is a cleaning, not a fix.
GateCatchesCost
Accessibility linter in the editorWrong roles, missing alt, click handlers on non-interactive elementsNear zero, and it teaches while it blocks
Automated scan in component testsRegressions in shared components, at the moment the component changesLow; the same rules as the audit tool, one layer earlier
Keyboard path in end-to-end testsFocus management in modals, menus and forms — the things a static scan cannot seeModerate; worth it for the critical flows only
Manual review for new componentsEverything in the right-hand column aboveHighest, so scope it to new shared components rather than every pull request
Turn scanning on for changed files before turning it on repository-wide. A gate that fails every build on day one gets switched off in week one, which is the same mechanic that defeats any late-introduced check — Frontend Testing — Unit, Component & E2E has the general version of the argument.
Concept
Two Ways Organisations Buy Their Way Into a Worse Position
Both are attractive precisely because they convert an engineering backlog into a purchase or a document, and both have made the underlying exposure larger rather than smaller.
ShortcutWhat it actually does
Accessibility overlay widgetsA script that adjusts the page at runtime. It cannot repair a control that has no accessible name or a flow with no keyboard path, it frequently interferes with the assistive technology a user has already configured, and organisations that installed one have still faced complaints. It is a purchase that feels like a fix
An optimistic conformance reportA published accessibility statement or vendor report claiming "supports" where the honest answer is "partially supports". Over-claiming is what converts a complaint into a documented misrepresentation, and it is checkable by anybody with a browser
The safe version of the second is dull and defensible: state what is not conformant, say what the workaround is, give a date, and provide a contact that a human answers. Regulators and procurement teams both respond far better to a known gap with a plan than to a claim that does not survive inspection — Section 508 — Accessibility as US Federal Law is where that document becomes a procurement requirement rather than a courtesy.
Concept
The Order That Actually Works
Put together, remediation has a sequence, and most of the value lands in the first three steps. 
1.  Regroup the report by component, not by page.
2.  Fix blockers on money-and-identity flows first.
3.  Turn on the linter and component scanning for changed files.
4.  Do the three manual passes on those same flows: keyboard, zoom, screen reader.
5.  Work the severe tier by component, in leverage order.
6.  Publish an honest statement with the remaining gaps and dates.
7.  Re-audit — and compare component counts, not instance counts.
One thing outperforms all of it: watch somebody who uses a screen reader or switch control try to complete your main flow. Half an hour of that reorders the backlog more accurately than any severity column, because it replaces a guess about impact with an observation of it — and it tends to end the argument about whether the work is worth funding.

🕸️ Technical SEO (Search Engine Optimization) Operations — Crawling, Indexing & Migrations Without Losing Traffic Shipping ▶
Concept
Crawled, Indexed and Ranking Are Three Different Things
SEO & Metadata for Developers covers what to put on a page. This card is about the part a developer actually gets paged for: a page that exists, looks correct, and does not appear in search. Nearly every such problem is a fault at one of three joints, and naming the joint first turns a vague complaint into a five-minute diagnosis.
StageQuestionWhere you check
DiscoveredDoes anything link to it, or list it in a sitemap?Sitemap, internal links, server logs
CrawledWas the URL (Uniform Resource Locator) fetched, and what status came back?Server logs — the only record of what was really requested
IndexedWas the fetched page stored, and under which canonical?Search Console's URL inspection
RankingIndexed, but does it appear for the query?Content and competition — no longer an engineering problem
The value of the split is that it separates work you can do from work you cannot. Discovery and crawling are engineering, entirely within your control, and measurable from your own logs. Ranking is not, and an engineer who accepts a ranking target has accepted a goal with no lever attached.
Concept
The Mistake Everyone Makes Once: robots.txt Does Not Remove Pages
A staging path leaks into the index. The instinct is to block it in robots.txt, and it is exactly wrong. robots.txt controls crawling; noindex controls indexing — and a crawler that is forbidden from fetching the page can never see the noindex you put in it. The page stays indexed, often with a snippet reading "no information is available", and now it is stuck there because you removed the only mechanism that could have cleared it. 
Wrong:  robots.txt: Disallow: /staging/     +  <meta name="robots" content="noindex">
        → never fetched → noindex never read → stays indexed indefinitely

Right:  robots.txt: (allow the crawl)       +  <meta name="robots" content="noindex">
        → fetched → noindex read → dropped from the index
        → only then, block the crawl if you still want to
ControlActually doesUse it for
robots.txtRequests that a URL not be fetched. Public, and advisorySaving crawl effort on infinite or worthless URL spaces
meta robots: noindexKeeps a fetched page out of the indexRemoving a page from search while it stays reachable
X-Robots-Tag headerThe same directive, at HTTP (HyperText Transfer Protocol) levelPDFs (Portable Document Format), images, anything with no HTML (HyperText Markup Language) head
rel=canonicalA hint about which duplicate is authoritativeParameter and duplicate URLs — not for removal, and it can be overruled
401 / 403Actually prevents accessStaging environments. This is the real answer, and it always was
410 GoneStates the page is permanently removedDeletions you want processed faster than a 404
Two things follow from "advisory". robots.txt is fetched by anyone, so listing /admin-beta/ in it publishes the path to every scanner on the internet — it is a hint file, never an access control. And a canonical is a suggestion: search engines regularly pick a different one, and the report will tell you they did, which is a fact worth checking before arguing that the tag is broken.
Reference
What Each Status Code Teaches a Crawler
Crawlers learn from status codes the way a cache does, and the operationally expensive errors are the ones that return a success code for a failure.
CodeInterpreted asWatch for
200A real page; index itReturning 200 with "Sorry, not found" — a soft 404, which pollutes the index with empty pages
301Permanent move; transfer signals, update the URLChains. Each hop costs time and some are abandoned — redirect once, to the final URL
302Temporary; keep the old URLUsed for permanent moves by accident, usually because it is the framework default
404Missing; retry occasionally, then dropNothing. A 404 for something absent is correct and needs no fixing
410Deliberately goneUse when you mean it; it is processed more decisively than 404
503Temporarily unavailable; come backThe right code for maintenance. A maintenance page served as 200 asks to be indexed as your content
5xx sustainedThe site is unhealthy; crawl lessCrawl rate drops after outages and recovers slowly — an availability incident has a tail
Concept
Migrations: the Redirect Map Is the Deliverable
Replatforming, restructuring URLs, or moving domains is where sites actually lose traffic, and it is nearly always the same failure: the redirect map was written after launch, from memory, by someone who did not have the old URL list.
StepDo itBecause
Inventory before you buildCrawl the old site and export every indexed URL, plus every URL with traffic or inbound linksAfter launch the old site is gone and the list is unrecoverable
Map old to new, one hopEvery old URL points directly at its final destinationChains lose time and sometimes stop being followed
Map to the closest equivalentNot to the homepageA mass redirect to the root is treated as a soft 404 and keeps nothing
Keep the old sitemap live brieflyServe it after launch for a few weeksIt is how crawlers rediscover the old URLs in order to see the redirects
Change one thing at a timeURLs, or design, or platform — not all three in one weekIf traffic drops you must be able to attribute it; simultaneous changes make the cause unrecoverable
Watch logs, not rankings, firstCrawl volume, status mix and error rate for two weeksRanking data lags by weeks; crawl errors show up the same day
Expect a dip. A well-executed migration usually loses some traffic for a few weeks while everything is re-crawled, and saying so beforehand is the difference between a known cost and an emergency — because the pressure to roll back peaks exactly when recovery is about to begin.
Concept
JavaScript, Crawl Budget & the Two Kinds of Performance Data
Three operational realities that come up on every modern site, each of which contradicts something people believe.
RealityWhat it means for the build
Rendering happens, but laterMajor crawlers execute JavaScript — on a second pass, from a queue. Content that only exists after a client-side fetch is discovered late, and content behind an interaction is not discovered at all. Server-render or prerender anything that must be indexed
Crawl budget is spent on junk firstFaceted navigation generates near-infinite URL combinations, and a crawler will happily spend its visit on ?sort=asc&colour=red&page=7 instead of your new pages. Canonicalise parameters, and block the genuinely infinite spaces from crawling
Lab and field data disagree, and field winsA Lighthouse run is one synthetic load on your machine. Field data is a rolling window of real visits on real devices and networks. When they conflict, the field number is the one that counts — and it is why a fast local score coexists with a failing report
That last row is the reconciliation people look for when Web Performance — Core Web Vitals passes locally and fails in the report: the metric is the same, the population is not. Field data also lags by weeks, so a fix deployed today shows up in the report long after the lab has stopped complaining — which is a reason to keep the deploy date written down beside the graph.
Concept
The Logs Are the Only Ground Truth
Every other source is an interpretation. Server logs record what was requested, when, by whom, and what you returned — which makes them the one place that can settle an argument about whether a page was ever fetched.
QuestionWhat the logs show
"Our new section isn't indexed"Whether it was ever requested. If not, it is a discovery problem — links and sitemap — and no amount of on-page work will help
"Crawling dropped after the release"The status mix on the release date. A jump in 5xx or in redirect hops explains it directly
"Are we wasting crawl on rubbish?"The share of requests going to parameter URLs, pagination and filters versus real content
"Is this traffic really a search engine?"Verify by reverse DNS (Domain Name System) on the requesting address. A large share of declared crawler traffic is something else wearing the name
The habit worth forming: before changing anything, establish which of the four stages is failing, and take the evidence from logs rather than from the dashboard. Most technical SEO work is troubleshooting a distributed fetcher you cannot instrument — so the parts you can instrument are worth more than they look.

🌍 Rendering at the Edge — CDNs (Content Delivery Network) & Edge Functions Shipping ▶
Concept
Compute Close to the User
A CDN caches static assets in hundreds of locations worldwide so users download from nearby. Edge functions push compute there too — run code milliseconds from the user.
ConceptDetail
CDN cachingStatic assets served from the nearest POP
Edge functionsLightweight compute at the edge (auth, redirects, A/B)
Image optimizationResize/format on the fly (WebP/AVIF) at the edge
Cache headersCache-Control, ETags, immutable hashed assets
Trade-off: edge runtimes are limited (no full Node APIs, short execution) — great for fast, small logic, not heavy work. Combined with hashed filenames + long cache TTLs (Time To Live), the edge makes global sites feel local.
🧩 WebAssembly — Native Speed in the Browser Platform ▶
Concept
When JavaScript Isn't Fast Enough
WebAssembly (Wasm) is a compact binary format that runs at near-native speed in the browser. Compile C/C++/Rust/Go to Wasm and call it from JS (JavaScript) for compute-heavy work.
Great forExample
Heavy computeImage/video editing, games, simulations
Porting native codeExisting C/C++ libraries to the web (FFmpeg, SQLite)
Beyond the browserWasm + WASI as a portable, sandboxed runtime (edge, plugins)
Not a JS replacement: Wasm can't touch the DOM (Document Object Model) directly and has call-overhead — reach for it for the hot compute path, not the whole app. Its bigger future may be server-side: a fast, secure, language-agnostic sandbox.
