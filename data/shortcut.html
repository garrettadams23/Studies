💙 PowerShell — Windows (and Cross-Platform) Scripting SHORTCUTS • Scripting ▶
POWERSHELL VS CMD
Why PowerShell Replaced Command Prompt
CMD (Command Prompt) is ancient — 1980s DOS heritage. PowerShell is a modern scripting environment built on .NET. Everything is an object (not just text), making it far more powerful. PowerShell Core (PS 7+) runs on Linux and Mac too — making it cross-platform. Windows admins and security teams must know it.
FeatureCMDPowerShell
Output typePlain text.NET objects (piped, filtered, sorted)
ScriptingBatch files (.bat) — limitedFull scripting language (.ps1) with loops, functions, classes
PipingText pipesObject pipes — access properties directly
Windows integrationLimitedFull access to WMI (Windows Management Instrumentation), .NET, COM, Registry
Cross-platformWindows onlyPowerShell 7+ runs on Linux/Mac
Security loggingMinimalTranscription, ScriptBlock logging
CORE CONCEPTS
Cmdlets, Objects, and the Pipeline
PowerShell commands are called cmdlets (pronounced "command-lets"). They follow a Verb-Noun naming pattern (Get-Process, Set-Item, New-Item). Output is objects with properties — you can access, filter, and pipe them.
# Get-Help is your best friend Get-Help Get-Process Get-Help Get-Process -Examples Get-Help *service* # find cmdlets about services # Basic navigation (aliases match Linux commands) ls # alias for Get-ChildItem cd C:\Users\Alice # alias for Set-Location pwd # Print Working Directory cat file.txt # alias for Get-Content cp source dest # alias for Copy-Item rm file.txt # alias for Remove-Item mkdir NewFolder # alias for New-Item -ItemType Directory # Object pipeline — output is objects, not text Get-Process # list all processes Get-Process | Where-Object {$_.CPU -gt 50} # filter by CPU Get-Process | Sort-Object CPU -Descending | Select-Object -First 10 Get-Process | Select-Object Name, CPU, WorkingSet
COMMON TASKS
PowerShell Cheat Sheet
# Services Get-Service # list all services Get-Service -Name "wuauserv" # Windows Update service Start-Service -Name "wuauserv" Stop-Service -Name "wuauserv" Restart-Service -Name "wuauserv" Set-Service -Name "wuauserv" -StartupType Disabled # Files and text Get-Content C:\log.txt # read file Get-Content C:\log.txt | Select-String "error" # grep equivalent "Hello World" | Out-File C:\output.txt Add-Content C:\log.txt "new line" # append # Network Test-NetConnection google.com # ping + port check Test-NetConnection google.com -Port 443 # test specific port Get-NetIPAddress # your IP addresses Resolve-DnsName google.com # DNS lookup Get-NetTCPConnection # netstat equivalent # System info Get-ComputerInfo # detailed system info Get-EventLog -LogName Security -Newest 20 # security log Get-WmiObject -Class Win32_LogicalDisk # disk info # Users Get-LocalUser # list local accounts New-LocalUser -Name "alice" -Password (ConvertTo-SecureString "P@ss!" -AsPlainText -Force) Add-LocalGroupMember -Group "Administrators" -Member "alice"
SCRIPTING
Writing PowerShell Scripts
# Variables start with $ $name = "Alice" $count = 42 $pi = 3.14159 # String interpolation Write-Host "Hello, $name!" # Hello, Alice! Write-Host "Pi is approximately $pi" # Arrays $fruits = @("apple", "banana", "cherry") $fruits[0] # apple $fruits.Count # 3 $fruits += "date" # add element # Hash tables (dicts) $user = @{ Name = "Alice"; Age = 30; Role = "Admin" } $user["Name"] # Alice $user.Role # Admin # If / ForEach / While if ($count -gt 10) { Write-Host "Big" } elseif ($count -gt 5) { Write-Host "Medium" } else { Write-Host "Small" } foreach ($fruit in $fruits) { Write-Host "I like $fruit" } 1..10 | ForEach-Object { Write-Host "Item $_" } # 1 to 10 # Functions function Get-Greeting { param([string]$Name = "World") return "Hello, $Name!" } Get-Greeting -Name "Alice"
EXECUTION POLICY
Why Your Script Won't Run
PowerShell's execution policy restricts which scripts can run. This is a security feature — not a permission system. On a new Windows machine, scripts are often blocked by default.
# Check current policy Get-ExecutionPolicy # Policy levels (most to least restrictive) Restricted # No scripts (default on Win clients) AllSigned # Only code-signed scripts RemoteSigned # Local scripts OK; downloaded must be signed Unrestricted # All scripts run (prompt for remote) Bypass # Nothing blocked (used in automation) # Set for current user (doesn't require admin) Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser # Run a script bypassing policy (one-time) powershell.exe -ExecutionPolicy Bypass -File myscript.ps1
🌳 Git Power User — Beyond add, commit, push SHORTCUTS • Version Control ▶
STASHING
Set Work Aside Temporarily
You're mid-change and suddenly need to switch branches for an urgent fix — but your work isn't ready to commit. git stash shelves your changes so you have a clean working directory, then restores them later.
git stash # shelve current changes git stash -u # include untracked files git stash list # see all stashes git stash pop # restore most recent & remove from list git stash apply # restore but KEEP in stash list git stash drop # delete a stash git stash save "wip: login" # named stash
REBASE
Rewrite History for a Clean Timeline
Rebasing moves your commits to start from a different base — useful for keeping a linear, clean history instead of merge bubbles. Golden rule: never rebase commits you've already pushed to a shared branch (it rewrites history others depend on).
# Update your feature branch with latest main (linear) git checkout feature git rebase main # replay your commits on top of main # Interactive rebase — clean up your last N commits git rebase -i HEAD~3 # edit/squash/reorder last 3 commits # In the editor: pick / squash / reword / drop / edit # If conflicts arise during rebase # fix files, then: git add <files> git rebase --continue git rebase --abort # bail out, restore original state
UNDOING THINGS
The Commands That Save You
GoalCommand
Unstage a file (keep changes)git restore --staged file
Discard local changes to a filegit restore file
Amend the last commitgit commit --amend
Undo last commit, keep changes stagedgit reset --soft HEAD~1
Undo last commit, keep changes unstagedgit reset HEAD~1
Nuke last commit and changes (danger)git reset --hard HEAD~1
Safely undo a pushed commitgit revert <hash> (makes a new inverse commit)
Recover "lost" commitsgit reflog (your safety net — shows ALL HEAD moves)
GIT BISECT
Binary Search to Find the Bug-Introducing Commit
A bug appeared somewhere in the last 200 commits but you don't know where. git bisect does a binary search — you test the midpoint, tell git "good" or "bad", and it homes in on the exact commit that broke things in ~log₂(n) steps.
git bisect start git bisect bad # current commit is broken git bisect good v1.0 # this old tag worked # Git checks out a commit halfway between. Test it, then: git bisect good # this one works # — or — git bisect bad # this one is broken # Repeat. Git narrows down to the exact culprit commit. git bisect reset # done — return to where you started # Automate it with a test script! git bisect run ./test.sh # git runs the script at each step
INSPECTING
Useful Investigation Commands
git log --oneline --graph --all # visual branch history git blame file.py # who changed each line and when git show <hash> # view a specific commit's changes git diff main..feature # compare two branches git log --grep="bug" # search commit messages git log -p file.py # full history of one file git log --author="alice" # commits by author
🪟 tmux — Never Lose a Session Again SHORTCUTS • Productivity ▶
WHY TMUX
The Persistent, Splittable Terminal
tmux (terminal multiplexer) solves two huge problems: (1) Persistence — your session keeps running on the server even if your SSH (Secure Shell) connection drops or you close your laptop. Reconnect and everything's exactly where you left it. (2) Layout — split one terminal into multiple panes and windows. For anyone who works on remote servers, tmux is life-changing. A long-running job no longer dies when your Wi-Fi hiccups.
THE PREFIX KEY
Everything Starts with Ctrl+b
tmux commands begin with a prefix — by default Ctrl+b — then a key. Notation: C-b means Ctrl+b, release, then press the next key. (Many people remap the prefix to Ctrl+a for ergonomics.)
# Session management (from the shell) tmux # start a new session tmux new -s work # named session "work" tmux ls # list sessions tmux attach -t work # reattach to "work" tmux kill-session -t work # THE killer feature: detach and reattach # C-b d → detach (session keeps running on the server) # Later: tmux attach → everything's still there

A Sensible ~/.tmux.conf Starter
# ~/.tmux.conf # Remap prefix to Ctrl+a (easier reach) unbind C-b set -g prefix C-a # Start windows/panes at 1, not 0 set -g base-index 1 # Enable mouse (scroll, click panes, resize) set -g mouse on # More scrollback history set -g history-limit 10000 # Easier splits that remember current path bind | split-window -h -c "#{pane_current_path}" bind - split-window -v -c "#{pane_current_path}" # Reload config without restarting: C-a r bind r source-file ~/.tmux.conf \; display "Reloaded!"
⚡ Text Processing Mastery — Combining the Classic Tools SHORTCUTS • Power User ▶
THE UNIX PHILOSOPHY
Small Tools That Do One Thing, Piped Together
The power of the command line comes from composing small, focused tools with pipes (|). Each tool does one thing well; the pipe feeds one's output into the next. Mastering a handful of these — and how to chain them — lets you answer questions about logs and data in seconds that would take ages in a GUI (Graphical User Interface).
GREP — FIND LINES
Search Text Like a Pro
grep "ERROR" app.log # lines containing ERROR grep -i "error" app.log # case-insensitive grep -r "TODO" ./src # recursive through dir grep -v "DEBUG" app.log # INVERT — lines WITHOUT DEBUG grep -c "404" access.log # count matching lines grep -n "fail" app.log # show line numbers grep -A3 -B3 "panic" app.log # 3 lines After + Before context grep -E "warn|error|fatal" app.log # regex (extended) OR grep -oE "[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+" log # extract just IPs
FIND — LOCATE FILES
Search the Filesystem by Any Attribute
find . -name "*.log" # by name pattern find / -type f -size +100M # files over 100MB find . -mtime -1 # modified in last 24h find /var/log -mtime +30 -delete # delete logs older than 30 days find . -type f -name "*.sh" -perm -u+x # executable scripts # find + exec / xargs — act on results find . -name "*.tmp" -exec rm {} \; # delete each match find . -name "*.py" | xargs grep "import os" # grep in matches
THE CLASSIC PIPELINE
cut · sort · uniq · awk — Together
# "Top 10 IPs hitting my web server" — a legendary one-liner cut -d' ' -f1 access.log | sort | uniq -c | sort -rn | head -10 # cut field 1 (IP) → sort → count dups → sort by count desc → top 10 # Count HTTP status codes awk '{print $9}' access.log | sort | uniq -c | sort -rn # Sum a column (e.g., total bytes transferred) awk '{sum += $10} END {print sum}' access.log # Unique users who logged in today grep "$(date +%Y-%m-%d)" auth.log | grep "session opened" \ | awk '{print $NF}' | sort -u # Find the 5 largest files under /var, human-readable find /var -type f -printf '%s %p\n' | sort -rn | head -5 \ | awk '{printf "%.1f MB %s\n", $1/1048576, $2}'

⌨️ Intermediate Vim — Editing as a Language SHORTCUTS • Power User ▶
THE BIG IDEA
Vim Is a Language: Verb + Motion
Vim's power isn't memorizing hundreds of commands — it's that commands compose like a language. You combine a verb (operator: what to do) with a motion (where). Learn a handful of each and you can express thousands of edits. d (delete) + w (word) = dw "delete word." Once it clicks, editing becomes thought-speed.

Tmux Survival Kit – Never Lose a Terminal Session Again

Concept

The problem tmux solves: "the SSH (Secure Shell) connection dropped, and I lost everything"

Tmux (terminal multiplexer) lets you create terminal sessions that keep running even after you disconnect — whether your laptop sleeps, your VPN (Virtual Private Network) drops, or you just want to walk away and resume later from a different machine. Without it, a long-running command in an SSH session dies the instant the connection does. With it, you simply reconnect and find everything exactly where you left it, still running.

Concept

The mental model: sessions, windows, and panes

ConceptThink of it as...Why it matters
SessionAn entire workspace — everything you're doing on this server right nowYou can detach from it and it keeps running; reattach later from anywhere
WindowA tab within that sessionSwitch between separate tasks (editing, monitoring logs, running tests) without separate connections
PaneA split within a window — multiple terminals visible side by sideWatch logs in one pane while running commands in another, all on one screen
Reference

The shortcuts that get you 90% of the way there

Every tmux command starts with a "prefix" key — by default Ctrl+b — released, then followed by another key. Below, "prefix" means "press Ctrl+b, let go, then press the next key."

ShortcutWhat it does
tmux new -s workStart a new named session called "work" (naming sessions makes them MUCH easier to find later)
prefix dDetach from the current session — it keeps running in the background
tmux attach -t workReattach to that session from anywhere — even a different computer
tmux lsList all running sessions — "what do I have going on right now?"
prefix cCreate a new window (tab) in the current session
prefix n / prefix pMove to the next / previous window
prefix %Split the current pane vertically (side by side)
prefix "Split the current pane horizontally (stacked)
prefix arrow-keyMove between panes in that direction
Hands-on

A realistic first session, start to finish

# 1. SSH into a remote server, then start a named session
ssh admin@server.example.com
tmux new -s deploy

# 2. Kick off something long-running — a deployment, a big sync, a build
./run_deployment.sh

# 3. Your laptop goes to sleep / VPN hiccups / you close the lid.
#    The deployment KEEPS RUNNING on the server — tmux doesn't care
#    that your connection dropped.

# 4. Reconnect later (even from a different machine entirely)
ssh admin@server.example.com
tmux attach -t deploy
# ...and there it is, exactly where you left it, still running

# 5. When you're completely done with it
exit   # closes the window/session from inside
# or from outside: tmux kill-session -t deploy
Mindset

Assume makes an ass out of you and me — name your sessions

"I'll remember which session is which" is a confident assumption at 2 PM and a source of genuine confusion at 2 AM when tmux ls shows four unnamed sessions and you can't recall which one has the thing you actually need. The thirty seconds it costs to type tmux new -s deploy-prod-db-migration instead of tmux new pays for itself the very first time you have more than one session running — which, if you use tmux at all regularly, will be sooner than you think.

🔑 API (Application Programming Interface) Keys & Gateways — Netlify · GitHub · REST (Representational State Transfer) DEV · WEB · DEPLOY ▶
Concept
What Is an API Key?
An API key is a unique string a server issues to identify and authorize a client. When you make a request to an external service (weather data, payment processor, AI model), you include the key so the server knows who you are and what you're allowed to do. Keys are like passwords for machines — they should never be hard-coded in source code or committed to Git.

Best Practices
Keeping API Keys Secure
RuleWhy It Matters
Never commit keys to GitOnce pushed (even deleted later), keys are in git history forever and can be scraped
Use .env files locally.env holds secrets for local dev — always add it to .gitignore
Use platform secret storesNetlify env vars, GitHub Actions secrets, AWS (Amazon Web Services) Secrets Manager — not plain config files
Least privilegeGrant only the minimum permissions the key actually needs — limits blast radius if leaked
Rotate regularlyExpire and replace tokens on a schedule; immediately rotate any key that may have been exposed
Separate keys per environmentDev, staging, and production should each have their own keys so a test leak doesn't hit prod
Use secret scanningGitHub scans pushes for known token formats and alerts you (or blocks the push) automatically
Use HTTPS onlySending a key over plain HTTP exposes it to anyone watching the network
